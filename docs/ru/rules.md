# Правила и вебхуки {#rules-and-webhooks}

Правила — это автоматизация «если — то» для ваших собственных документов. У каждого правила есть
триггер, условия и действия: когда срабатывает триггер и выполняются все условия, выполняются
действия. Типичные примеры:

- **Счета** — если тип документа *Счёт*, ИИ заполняет *Сумму*, *Срок оплаты* и *IBAN* по
  инструкциям, которые касаются только счетов, и добавляется тег *к оплате*.
- **Крупные суммы** — если *Сумма* больше 1000, документ отправляется во «Входящие» на проверку.
- **Автоматизация** — если корреспондент — ваш арендодатель, вызывается вебхук n8n, Home Assistant
  или Zapier с документом.

Правила находятся в разделе **Ещё → Правила**. У каждого пользователя свои; правило действует
только на документы своего владельца.

---

## Триггеры {#triggers}

- **Документ обработан** — после того как извлечение ИИ записало метаданные, в том числе при
  повторной обработке. Документы, импортированные с сохранением метаданных (Paperless-ngx, Papra),
  не обрабатываются, поэтому для них этот триггер не срабатывает.
- **Я меняю его теги или поля** — после того как вы изменили в приложении теги, тип документа,
  корреспондента или другое поле документа. Изменение заголовка или краткого содержания не
  считается. Правила выполняются коротким заданием для документа; документ во «Входящих» там и
  остаётся.

У правила могут быть оба.

## Условия {#conditions}

Должны выполняться все условия правила. Правило без условий срабатывает для каждого документа.

| Поле | Сравнения |
| --- | --- |
| Тип документа, корреспондент, поля с выбором | равно, не равно, заполнено, пусто |
| Теги | включают, не включают |
| Заголовок, текст документа, текстовые поля | содержит, не содержит, подходит под шаблон, заполнено, пусто |
| Числовые поля, уверенность ИИ | равно, больше, меньше, заполнено, пусто |
| Поля с датой | равно, позже, раньше, заполнено, пусто |

Текстовые сравнения не учитывают регистр. Шаблон — это [регулярное выражение в синтаксисе
Go](https://github.com/google/re2/wiki/Syntax); оно учитывает регистр, если не начинается с
`(?i)`. Уверенность ИИ — число от 0 до 1; извлечение с уверенностью ниже 0,5 и так попадает во
«Входящие».

## Действия {#actions}

- **Добавить тег / Убрать тег**
- **Задать** тип документа, корреспондента или другое поле.
- **Отправить во «Входящие» на проверку** — документ ждёт, пока кто-нибудь не отметит его
  проверенным.
- **Заполнить поля с помощью ИИ** — один дополнительный запрос к модели извлечения, только про
  отмеченные поля, с вашими инструкциями. Поля, у которых уже есть значение, его сохраняют. Сами
  поля создаёт администратор в разделе **Админ-панель → Поля документов**.
- **Вызвать вебхук** — см. ниже.

## Порядок {#order}

Правила выполняются сверху вниз, каждое один раз. Правило видит то, что изменили правила выше: за
правилом, которое заполняет *Сумму* с помощью ИИ, может идти правило, которое её проверяет.
Изменение никогда не запускает правило второй раз. Действия выполняются в указанном порядке, кроме
вебхуков: они отправляются после того, как всё остальное сохранено.

Если действие выполнить не удалось — модель не ответила, вебхук недоступен, тег из правила
удалён, — остальные действия всё равно применяются, а в шагах обработки документа шаг
**Выполнить правила** отмечен как неудачный с причиной. Там же перечислены сработавшие правила.

## Вебхуки {#webhooks}

Вебхук — это `POST` с таким JSON-телом:

```json
{
  "event": "rule.matched",
  "trigger": "processed",
  "rule": { "id": "…", "name": "Счета" },
  "document": {
    "id": "…",
    "title": "Счёт R-2026-001",
    "summary": "…",
    "document_date": "2026-10-01",
    "document_type": "Счёт",
    "correspondent": "ООО «Акме»",
    "tags": ["к оплате"],
    "fields": { "Сумма": 129.9, "Срок оплаты": "2026-10-31" },
    "processing_status": "completed"
  }
}
```

С секретом для подписи заголовок `X-Lemmary-Signature` содержит `sha256=` и шестнадцатеричный
HMAC-SHA256 тела запроса по этому секрету. Сравнивайте его за постоянное время, прежде чем
доверять вызову. Любой ответ 2xx считается успехом; на вебхук отводится 10 секунд, повторов нет.

Вебхуки проходят ту же проверку адресов, что и удалённый импорт: link-local-адреса и адреса
облачных метаданных запрещены всегда, а частные и loopback-адреса — если сервер запущен с
`IMPORT_ALLOW_PRIVATE=0`.
