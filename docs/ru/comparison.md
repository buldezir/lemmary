# Lemmary, Paperless-ngx и Papra {#lemmary-vs-paperless-ngx-vs-papra}

Все три продукта превращают коллекцию файлов на собственном сервере в архив
документов с поиском. Lemmary идёт дальше: он создан, чтобы упорядочивать архив
за вас и превращать его в источник, которому можно задавать вопросы и который можно исследовать, без того чтобы
сначала выстраивать сложную систему хранения.

- **Lemmary** — личный архив, построенный вокруг ИИ. Он автоматически извлекает подробные
  метаданные, может отвечать на вопросы об отдельном документе, а также искать, читать и
  обобщать сведения по всему архиву — со ссылками на источники. Агенты
  могут искать и читать тот же архив через MCP, а там, где разрешил администратор, — и изменять его.
- **Paperless-ngx** — зрелая система управления документами, ориентированная на сканы. Из трёх у неё
  самая развитая модель хранения, автоматизация, редактирование документов, права доступа и
  экосистема клиентов — ценой более сложной инфраструктуры и большего ручного
  упорядочивания.
- **Papra** — минималистичный архив для совместной работы. В центре — организации, совместный доступ,
  публичный API и гибкое хранилище, а её ИИ-функция сосредоточена
  на автоматической расстановке тегов, а не на поиске по архиву и ответах на его основе.

Это сравнение возможностей, а не бенчмарк. «Встроено» всё равно может требовать
настройки, учётных данных или дополнительного сервиса. Все три столбца сверены
**7 октября 2026 года**: Lemmary — с этой документацией, Paperless-ngx — с
версией v3.3.0, Papra — с версией 26.7.0 и документацией проектов по ссылкам.
Прежде чем делать выбор на основании одной функции, проверьте исходный проект.

## Сравнение возможностей {#feature-comparison}

| Область | Lemmary | Paperless-ngx | Papra |
| --- | --- | --- | --- |
| Основное назначение | Архив документов, который упорядочивает себя сам и поддерживает исследование по всему архиву со ссылками на источники | Традиционный процесс управления документами для сканированных и цифровых записей | Простое хранение документов и совместная работа |
| Самостоятельный хостинг | Компактная конфигурация по умолчанию: один контейнер приложения и один постоянный том; [PocketBase также поддерживает S3-совместимое хранилище документов](/ru/storage#document-files), а сайдкары для локального OCR и эмбеддингов необязательны — в Docker или [нативно на Mac с Apple Silicon](/ru/local_ai_macos) | Docker Compose или «голое железо»; помимо приложения требуется Redis-совместимый брокер, поддерживаются SQLite, PostgreSQL или MariaDB | Один образ Docker для базовой установки; поддерживаются файловая система, S3-совместимое хранилище и Azure Blob |
| Загрузка и приём | Загрузка через веб файлов, папок и zip-архивов; [отслеживаемая папка приёма](/ru/setup#ingest-folder), подпапки которой становятся тегами; [вложения из почтового ящика IMAP](/ru/setup#ingest-from-imap); [прямое сканирование с сетевых сканеров AirScan/eSCL](/ru/scanning); частично совместимый с Paperless-ngx REST API; прямой перенос из Paperless-ngx и Papra, отдельный экспорт заказов Amazon и приём PDF с несколькими документами | Загрузка через веб/API, отслеживаемая папка приёма, почтовые учётные записи и правила | Загрузка через веб/API/CLI, отслеживаемые папки организаций и входящая почта |
| OCR и извлечение текста | Mistral OCR, Google Cloud Vision, OpenAI-совместимая или Anthropic модель для файлов, [подписка ChatGPT](/ru/chatgpt_login) или [локальный сайдкар Docling](/ru/local_ocr) (RapidOCR, EasyOCR, Tesseract или Apple Vision на Mac); встроенное извлечение для текстовых и офисных файлов; если задан язык результата, OCR-текст можно по запросу прочитать в переводе | Локальный OCR Tesseract на 100+ языках с необязательным удалённым Azure AI OCR; создаёт архивный PDF/A рядом с оригиналом, но по умолчанию пропускает цифровые PDF, в которых уже есть текст | Внутреннее извлечение с Tesseract по умолчанию; также поддерживаются Mistral OCR, Docling, Azure Document Intelligence и собственные HTTP-экстракторы |
| Автоматическое упорядочивание | Каждый обработанный документ может автоматически получить от LLM название, дату, тип, корреспондента и краткое содержание, а также теги, выбранные из списка, который ведёте вы, — LLM присваивает их, но никогда не придумывает новые. Правила, написанные администратором, направляют извлечение; документы, отложенные на проверку, получают до трёх предложенных новых тегов на утверждение; новый тег можно присвоить с помощью ИИ документам, обработанным до его появления; при включённом [связывании документов](/ru/setup#related-documents) документ связывается с другими, у которых тот же номер счёта, заказа, договора, полиса, дела или брони либо близкое содержание | Правила сопоставления и обучаемый классификатор присваивают теги, корреспондентов, типы и пути хранения; необязательная LLM предлагает метаданные на проверку, либо действие рабочего процесса применяет их автоматически и может создавать недостающие теги, корреспондентов и типы | Правила могут присваивать теги; необязательная LLM может присваивать существующие теги или создавать новые, но не извлекает тот более широкий набор метаданных, что Lemmary |
| Модель метаданных | Название, дата, тип, корреспондент, цветные теги, краткое содержание, редактируемый OCR-текст, заданные администратором [пользовательские поля](/ru/setup#custom-fields) типа «текст», «число», «дата» и «выбор из списка», которые заполняет извлечение, с готовыми наборами полей для типичных бумаг в один клик, и двусторонние [связи между документами](/ru/setup#related-documents) | Теги, корреспонденты, типы документов, пути хранения, архивные серийные номера, заметки и типизированные пользовательские поля, включая двусторонние ссылки на документы | Теги, заметки и типизированные пользовательские свойства на уровне организации, включая ссылки на другие документы |
| Обычный поиск | Полнотекстовый поиск по OCR-тексту, метаданным и значениям пользовательских полей с поиском по префиксу и точными фразами в кавычках, фильтры (включая «все указанные теги», «без тегов» и «без даты»), временная шкала дат и входящие для проверки — всё доступно без модели эмбеддингов | Ранжированный полнотекстовый поиск с расширенным синтаксисом запросов и необязательным нечётким совпадением, поиск похожих документов («More like this»), фильтры, сохранённые представления и настраиваемая панель | Полнотекстовый поиск, фильтры запросов, поиск по пользовательским свойствам и сохранённые поиски |
| ИИ-поиск и чат | Процесс, наиболее ориентированный на исследование: **поиск с помощью ИИ** находит документы по ключевым словам и, при желании, по эмбеддингам, а с моделью эмбеддингов и строка поиска в списке документов находит документы по смыслу; **Deep Research** читает и обобщает сведения из многих документов со ссылками на источники, на необязательной отдельной расширенной модели, а его чаты могут ветвиться; **Спросить ИИ** — чат с одним документом. Оба могут [искать в интернете](/ru/ai_providers#the-web-search-provider), когда читатель это включает, а в чате можно сменить модель. Языковые модели работают по API-ключам (OpenAI, Anthropic, OpenRouter, Mistral, Opencode Go) или по подписке ChatGPT; эмбеддинги можно считать [на собственном оборудовании](/ru/local_embeddings) | Необязательные эмбеддинги служат опорой для предложений метаданных от LLM и чата со ссылками на источники по одному документу или по всем документам, доступным пользователю, но отдельного многошагового режима исследования нет | Чат по архиву и семантический поиск не описаны; текущая поддержка ИИ — автоматическая расстановка тегов |
| Инструменты для PDF и версий | Можно вручную разделить PDF с несколькими документами при приёме или попросить модель предложить места разреза | Объединение, разделение, поворот, удаление и перестановка страниц; хранение нескольких версий файла в одном документе | Аналогичный редактор PDF или история версий документов не описаны |
| Пользователи и совместный доступ | Несколько учётных записей и отдельные библиотеки для каждого пользователя; документ можно открыть только для чтения другим учётным записям на том же экземпляре; нет публичных ссылок на документы и общих рабочих пространств | Пользователи, группы, глобальные и объектные права доступа, владение, публичные ссылки с истечением срока, пакеты и отправка по почте | Организации с ролями владельца, администратора и участника; у ссылок для общего доступа могут быть срок действия и пароль |
| Аутентификация | Пароль, вход через OAuth2-провайдер и ключи доступа; двухфакторной аутентификации по TOTP нет | Пароль с необязательной двухфакторной аутентификацией по TOTP, вход через OIDC и социальные сети или по заголовку обратного прокси; вход по паролю можно отключить; ключей доступа нет | Пароль, вход через GitHub и Google, настраиваемые провайдеры OAuth2/OIDC и необязательная двухфакторная аутентификация по TOTP; ключей доступа нет |
| Языки интерфейса | Английский, немецкий и русский — для интерфейса, ошибок API и этой документации | Около 37, переводятся на Crowdin | 17 в веб-приложении |
| Автоматизация и интеграции | Полный асинхронный конвейер обработки OCR и ИИ, [MCP-сервер](/ru/mcp), чтобы агенты могли искать и читать архив, а там, где разрешил администратор, — и изменять его, совместимое подмножество API Paperless-ngx для существующих клиентов и необязательные метрики Prometheus | Событийные рабочие процессы, почтовые правила, вебхуки, скрипты, полноценный REST API и большая экосистема сторонних клиентов | Правила расстановки тегов, API-ключи с областями действия, REST API, TypeScript SDK, CLI и вебхуки |
| Импорт, экспорт и восстановление | Самый прямой переход с Paperless-ngx или Papra — Lemmary забирает данные из работающего экземпляра через его API, — а также переносимый zip всей библиотеки или отфильтрованной выборки с оригиналами, OCR, метаданными, миниатюрами и таксономией для резервного копирования и восстановления | Экспортёр/импортёр всего экземпляра для переноса и резервного копирования; выбранные документы можно скачать zip-архивом с файлами без метаданных; корзина на 30 дней | CLI-импортёр экспортов Paperless-ngx и инструменты переноса хранилища; экспорта библиотеки нет, поэтому для резервного копирования нужно отдельно сохранять настроенную базу данных и хранилище документов |
| Шифрование хранимых данных | Самая широкая встроенная защита: необязательное зашифрованное хранилище шифрует базу данных, файлы документов, превью и сохранённые векторы; оно запускается заблокированным и расшифровывает данные в оперативную память. Файловое хранилище S3 в PocketBase и зашифрованное хранилище — альтернативные конфигурации, поскольку зашифрованное хранилище не допускает незашифрованного внешнего хранения файлов | Встроенного шифрования хранимых данных нет; разработчики предупреждают, что документы хранятся в открытом виде, и рекомендуют доверенный хост | Необязательное шифрование файлов документов AES-256-GCM с ротацией ключей и отдельный необязательный ключ шифрования базы данных; по умолчанию оба выключены, а при одном лишь шифровании файлов извлечённый текст и метаданные остаются в открытом виде |

## Переход между ними {#moving-between-them}

Lemmary может забирать оригиналы и выбранные метаданные напрямую из Paperless-ngx.
Его интерфейс `/api/` также реализует полезное подмножество REST API
Paperless-ngx, так что совместимые мобильные клиенты могут просматривать и загружать документы, но Lemmary **не является
полной заменой сервера Paperless-ngx**: рабочие процессы, права доступа, сохранённые представления, пользовательские
поля и многие эндпоинты находятся за пределами этого слоя совместимости. См.
[Совместимость с API Paperless-ngx](/ru/paperless_ngx).

Lemmary также может забрать оригиналы, теги, даты и извлечённый текст из каждой
организации Papra, доступной API-ключу; заметки и пользовательские свойства Papra
не переносятся. См. [Импорт из Papra](/ru/setup#importing-from-papra).
