# Хранение данных {#storage}

Lemmary хранит постоянные данные в трёх местах: SQLite, хранилище файлов документов и
эмбеддинги в SQLite. Поисковые индексы — одноразовые копии, построенные из
этих постоянных данных.

| Данные | Расположение по умолчанию | С файловым хранилищем S3 |
| --- | --- | --- |
| База данных | `/app/pb_data/data.db` | Остаётся локально |
| Исходные файлы и миниатюры | `/app/pb_data/storage/` | Хранятся в настроенном S3-совместимом бакете |
| Векторы эмбеддингов и их состояние | Таблицы внутри `data.db` | Остаются локально |
| Полнотекстовый и векторный индексы | `/app/pb_data/bleve/` | Остаются локально |

## База данных {#database}

PocketBase использует SQLite. `data.db` содержит метаданные документов, извлечённый OCR-текст,
теги и прочую таксономию, пользователей, настройки, задания обработки, сохранённые чаты
и векторы эмбеддингов. Делайте резервную копию базы данных вместе с файлами документов:
ни то, ни другое по отдельности не является полным архивом.

## Файлы документов {#document-files}

По умолчанию PocketBase записывает загруженные исходники и сгенерированные миниатюры в
`pb_data/storage/`. В Docker том `app_data` сохраняет этот каталог вместе с
базой данных.

Вместо этого PocketBase может хранить эти файлы в S3-совместимом сервисе. Войдите
в интерфейс администратора PocketBase по адресу `/_/`, откройте **Settings → Files storage** и
включите S3, указав бакет, регион или эндпоинт, ключ доступа и секрет для этого
сервиса. В S3 переносятся только файлы записей: сохраните локальный том `pb_data`, потому что
в нём по-прежнему находятся SQLite и поисковые индексы.

Файловое хранилище S3 и [зашифрованное хранилище Lemmary](/ru/encryption) — взаимоисключающие
конфигурации. Зашифрованное хранилище отказывается запускаться, если в PocketBase включено хранение в S3,
потому что файлы, записанные вне хранилища, не получили бы его
шифрования.

## Эмбеддинги {#embeddings}

Когда настроена модель эмбеддингов, Lemmary разбивает OCR-текст каждого документа
на фрагменты. Векторы float32 и состояние эмбеддингов хранятся в «сырых» таблицах SQLite
внутри `data.db`; в S3 они не попадают. Фрагмент хранится как пара
байтовых смещений в OCR-тексте, а не как вторая его копия.

Deep Research выполняет запросы к производному векторному индексу Bleve в `pb_data/bleve/chunks`.
Этот индекс можно удалить и перестроить из векторов в SQLite без
повторного обращения к провайдеру эмбеддингов. Обычный полнотекстовый индекс рядом с ним,
в `pb_data/bleve/documents`, тоже производный и может быть перестроен.

Объём хранилища эмбеддингов растёт с числом фрагментов и размерностью векторов. См.
[во что обходятся эмбеддинги](/ru/ai_providers#what-embeddings-cost) и
[Локальные эмбеддинги](/ru/local_embeddings) — о расчёте объёма и вариантах провайдеров.
