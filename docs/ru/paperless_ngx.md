# Совместимость с API Paperless-ngx {#paperless-ngx-api-compatibility}

Lemmary предоставляет REST API, совместимый с paperless-ngx, на том же хосте, что и PocketBase (например, `http://127.0.0.1:8090/api/`). Бэкенд реализует эндпоинты, которых сторонние клиенты ожидают для аутентификации, документов, тегов, корреспондентов, типов документов и связанных метаданных.

Совместимость намеренно частичная: распространённые сценарии чтения и записи работают, но доступны не все возможности paperless-ngx (например, некоторые эндпоинты списков возвращают пустые заглушки там, где у Lemmary нет соответствующих данных).

## Идентификаторы документов {#document-ids}

Paperless-ngx адресует записи целочисленными идентификаторами; PocketBase использует строки из 15 символов. Lemmary хранит `ngx_id` для каждого документа, тега, корреспондента и типа документа; начальное значение вычисляется из хеша идентификатора PocketBase, поэтому идентификаторы, выданные до появления этого столбца, по-прежнему указывают на те же записи. Он уникален в пределах учётной записи, присваивается при создании и больше никогда не меняется — клиенты его кэшируют, а swift-paperless использует в качестве ключа своего кэша миниатюр URL, который его содержит.

Обновление нумерует существующую библиотеку за одну миграцию. Если у двух записей одной учётной записи начальные значения совпадают, второй присваивается следующий свободный идентификатор; до появления столбца вторая запись была полностью недоступна через API paperless.

## Фильтры списка документов {#document-list-filters}

`GET /api/documents/` понимает фильтры, которые клиенты реально отправляют:

| Фильтр | Параметры |
| --- | --- |
| Полный текст | `query` |
| Название и содержимое | `title_content`, `title__icontains`, `content__icontains` |
| Теги | `tags__id`, `tags__id__all`, `tags__id__in`, `tags__id__none`, `is_tagged` |
| Тип документа | `document_type__id`, `document_type__id__in`, `document_type__id__none`, `document_type__isnull` |
| Корреспондент | `correspondent__id`, `correspondent__id__in`, `correspondent__id__none`, `correspondent__isnull` |
| Дата документа | `created__date__{gt,gte,lt,lte}`, `created__{gt,gte,lt,lte}`, `created__year` |
| Дата загрузки | `added__date__{gt,gte,lt,lte}`, `added__{gt,gte,lt,lte}`, `added__year` |
| Владелец | `owner__id`, `owner__id__in`, `owner__id__none`, `owner__isnull` |
| Конкретные документы | `id`, `id__in` |
| Постраничный вывод и форма ответа | `page`, `page_size`, `ordering`, `truncate_content`, `fields` |

Фильтры комбинируются, а `count` всегда соответствует отфильтрованному набору, поэтому листать отфильтрованный список безопасно.

Две из этих групп требуют пояснения о точности и области действия:

- **`added__{gt,gte,lt,lte}` сравнивают момент времени целиком**, поэтому `added__gt=2025-06-15T10:00:00Z` возвращает загрузки, сделанные позже тем же утром. Формы `added__date__` сравнивают день, как и все сравнения по `created`: собственная дата документа не содержит времени суток. Документ без собственной даты отвечает на день своей загрузки — именно эту дату клиент для него и показывает.
- **Фильтры по владельцу принимаются, но не применяются.** Любой документ, который может вернуть этот API, принадлежит вызывающему либо открыт ему другой учётной записью только для чтения, поэтому указание этих владельцев ничего не сужает, а указание кого-либо ещё ничего не находит. Документ, к которому открыт доступ, выводится в списке, запрашивается, скачивается и ищется так же, как ваш собственный, несёт теги, корреспондента и тип своего владельца и отвечает на `PATCH` и `DELETE` кодом `404`.

Три вещи намеренно работают иначе, чем в paperless-ngx:

- **Фильтр, который Lemmary не может выполнить, даёт `400`, а не неотфильтрованную страницу.** В Lemmary нет путей хранения и архивных серийных номеров, а его [пользовательские поля](/ru/setup#custom-fields) через этот API недоступны (`/api/custom_fields/` ничего не возвращает), поэтому запрос с фильтром по любому из них отклоняется с `{"detail": "Unsupported filter \"…\"."}`. Вернуть `200`, проигнорировав фильтр, было бы хуже: клиент показал бы результат так, будто фильтр применён, и «документы с тегом Invoice» незаметно превратились бы во весь архив.
- **Текстовый поиск находит целые слова, а не подстроки.** Все четыре текстовых фильтра проходят через тот же индекс Bleve, что и поле поиска в веб-интерфейсе, а он разбит на токены. Запрос `rechn` находит `Rechnung` только как *префикс* и только если ни один документ не содержит `rechn` как целое слово; `rechnung` находится напрямую. Фрагмент внутри слова (`echnung`) ничего не находит, а термин, содержащий цифру, никогда не используется как префикс.
- **Отфильтрованный текстовый поиск перебирает не более 5000 совпадений.** Сверх этого возвращаемый `count` занижен — но последовательно, поэтому ссылки постраничного вывода никогда не указывают дальше того, что можно отдать.

Результаты ранжируются по релевантности, если задан текстовый фильтр, а `ordering` отсутствует, равен `score`, `-score` или полю, по которому этот сервер не сортирует, — так же поступает и paperless-ngx. Любой другой `ordering` обрабатывается базой данных. `ordering=id` сортирует по целочисленному идентификатору, который показан клиенту, а `ordering=created` — по той же дате, что указана в ответе. Список без текстового фильтра и без распознанного `ordering` возвращается начиная с самых новых загрузок.

## Подключение внешних клиентов {#connecting-external-clients}

1. Укажите в клиенте URL вашего сервера Lemmary (схема + хост + порт, без суффикса `/api` — клиенты добавляют его сами).
2. Войдите под учётной записью пользователя PocketBase. Эндпоинт `/api/token/` принимает те же имя пользователя и пароль, что и веб-интерфейс, и возвращает долгоживущий JWT (на десять лет). Клиенты Paperless-ngx сохраняют этот токен и не обновляют его; это не пятидневная сессия веб-интерфейса. Смена пароля учётной записи делает его недействительным.
3. Клиенты, отправляющие `Authorization: Token <jwt>` (в стиле paperless-ngx), поддерживаются наравне со стандартными Bearer-токенами.

Версии API 9 и 10 принимаются через заголовок `Accept` (`application/json; version=9`).

## Задачи {#tasks}

`GET /api/tasks/` сообщает о заданиях обработки Lemmary как о задачах paperless, начиная с самых новых, не более 100 за один ответ. `POST /api/acknowledge_tasks/` (и `/api/tasks/acknowledge/` — его название начиная с paperless-ngx 2.14) скрывает их по идентификатору.

Подтверждение хранится в столбце `ngx_acknowledged` таблицы `processing_jobs`, который читает и записывает только этот API: собственный интерфейс Lemmary показывает состояние обработки на документе и не знает понятия его скрытия. `acknowledged=true` и `acknowledged=false` фильтруют по нему; без этого параметра возвращаются оба варианта.

## Импорт из Paperless-ngx {#importing-from-paperless-ngx}

Любой вошедший пользователь может перенести библиотеку Paperless-ngx в свою учётную запись Lemmary. Удалённый API-токен аутентифицирует конкретного пользователя ngx, поэтому импорт выполняется от имени текущего локального пользователя, а не администратора.

1. Откройте **Импорт** в меню **Ещё**, затем вкладку **Paperless-ngx** (или перейдите на `/import/ngx`).
2. Введите базовый URL удалённого Paperless-ngx и API-токен из профиля этого экземпляра.
3. Выберите режим импорта:
   - **Сохранить метаданные Paperless-ngx** (`preserve`): создаёт или обновляет теги, корреспондентов и типы документов по имени; скачивает каждый документ вместе с его OCR-текстом `content`, названием, датой и связями с таксономией. Превью и поиск дубликатов по-прежнему выполняются; извлечение метаданных с помощью ИИ пропускается, чтобы сохранить удалённые метаданные.
   - **Импортировать только файлы и обработать заново** (`reprocess`): скачивает только исходные файлы и ставит в очередь полный конвейер OCR + ИИ, как для новой загрузки.
4. Запустите импорт. Точные дубликаты файлов (с той же контрольной суммой) пропускаются.

Тот же сценарий доступен как `POST /api/app/import/ngx` с JSON-телом `{ "url": "...", "api_key": "...", "mode": "preserve" | "reprocess" }`. Запрос возвращает `202 Accepted` с `{ "job_id", "status": "running" }`. Опрашивайте `GET /api/app/import/ngx/status?job_id=...`, пока `status` не станет `completed` (с `result`) или `failed` (с `error`). Состояние задания хранится в памяти только для работающего процесса. Для одного пользователя одновременно может выполняться один импорт. `mode` по умолчанию равен `preserve`. API-ключ не сохраняется.

Импорт обращается только к URL, указанному вызывающим. Частные, loopback- и link-local-адреса по умолчанию заблокированы (в том числе после перенаправлений). Задайте `IMPORT_ALLOW_PRIVATE=1`, если удалённый экземпляр Paperless-ngx находится в частной сети; адреса облачных метаданных остаются заблокированными.

## swift-paperless (iOS) {#swift-paperless-ios}

[swift-paperless](https://github.com/paulgessinger/swift-paperless) — основной мобильный клиент, на котором проверяется этот API. Просмотр документов и их подробностей, поиск, фильтрация и загрузка в целом работают. Некоторые специфичные для paperless-ngx настройки или расширенные функции могут отсутствовать или ничего не делать, потому что Lemmary не реализует paperless-ngx в полном объёме.

При открытии списка документов запрашиваются 250 документов, а затем миниатюра для каждого из них, каждая отдельным `GET /api/documents/{id}/thumb`: в paperless-ngx нет пакетного эндпоинта для миниатюр, а swift-paperless заранее загружает всю страницу, а не только видимые строки. Такой всплеск ожидаем и возникает только при холодном кэше: миниатюры отдаются с `Cache-Control` на 30 дней, а приложение ведёт собственный дисковый кэш с ключом по URL.

Если приложение начинает получать 401, хотя при добавлении сервера всё работало, один раз удалите и снова добавьте сервер, чтобы оно получило новый токен. Токены, выданные до появления долгоживущих JWT для `/api/token/`, истекают через пять дней и не могут быть продлены на месте.
